## 一、设计目标

### 1.1 核心参考系统

**edict 三省六部制系统特点**：
- 🎭 **古代官制主题**：采用唐朝三省六部制（中书省、门下省、尚书省）作为架构隐喻
- 📊 **实时看板**：Kanban卡片式布局，动态展示任务流转状态
- 🔄 **五阶段流程**：旨意→中书→门下→六部→回奏
- 📜 **奏折归档**：任务完成后自动生成完整的审计报告
- 🤖 **Agent可视化**：实时显示Agent思考过程和工具调用

### 1.2 投资分析业务映射

| 三省六部制元素 | 投资分析对应 | 说明 |
|--------------|------------|------|
| **圣旨（旨意）** | 股票分析请求 | 用户输入股票代码发起分析 |
| **中书省** | 产业链分析Agent | 起草分析（数据收集） |
| **门下省** | Commander审核 | 质量把关（预审） |
| **六部** | 基本面分析Agent | 执行具体分析（财务分析） |
| **回奏** | 最终报告生成 | 完整报告归档到奏折阁 |

**关键元素**：
1. **流程时间线**（Pipeline Strip）
   - 显示5个阶段：输入→产业链→审核→基本面→报告
   - 每个节点显示状态：完成✅ / 进行中🔄 / 等待⏸
   - 使用渐变背景突出当前阶段

2. **状态标签**
   - 部门标签：中书省(产业链)、门下省(审核)、户部(基本面)
   - 状态颜色：已完成、进行中、等待中

3. **心跳指示器**
   - 绿色心跳：正常运行
   - 黄色心跳：处理中
   - 红色心跳：异常

### 5.2 数据流设计

```
用户输入股票代码
    ↓
创建分析任务（圣旨）
    ↓

    ↓
完成 → 回奏（生成报告）
    ↓
归档到奏折阁
```
