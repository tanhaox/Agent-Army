## 🎯 文档维护规范

### 命名规范
```
✅ 正确命名：
- ARCHITECTURE_OPTIMIZATION_TASKS.md (全大写，下划线分隔)
- Phase_3.1_完成报告.md (中文，简洁明了)
- 00-快速开始.md (数字前缀，表示优先级)

❌ 错误命名：
- bug fix report.md (小写，空格分隔)
- report-2026-03-14-final-v2.md (版本混乱)
- 新建文本文档.md (无意义命名)
```

### 归档规范
```
临时报告归档时机：
1. Phase完成后1周
2. 任务完成后确认无需频繁查看
3. 有更新的正式文档替代

归档目录命名：
docs/archived/YYYY-MM-DD-PhaseN-Description/
```

### 更新规范
```
核心文档更新时机：
1. 完成重要任务（如Phase完成）
2. 修复重大问题（如P0修复）
3. 架构调整
4. 添加新功能

更新内容要求：
- 更新版本号
- 更新最后修改时间
- 记录变更内容
- 保持向后兼容
```
