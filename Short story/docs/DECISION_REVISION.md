## 📋 决策生命周期

```
[草案] draft → [锁定] locked → [执行中] executing → [修订中] revising → [归档] archived
                          ↓                                          ↓
                       [争议]                                  [新版本]
                                                                     ↓
                                                                [锁定 2] locked-2
```

---

## 🔧 决策修订流程（5 步）

### 步骤 1：识别冲突
- 任何决策变更都应明确指出 **与哪条已锁定决策冲突**
- 例：`F3 半自动伏笔` 与 `001 全部手标伏笔` 冲突

### 步骤 2：明确冲突级别
- **L1 不兼容**：完全反转（必须同时修订原决策）
- **L2 部分冲突**：扩展或限定（保留原决策主体，补充新内容）
- **L3 仅相关**：不冲突但相关（在新文档里引用，不修订原文档）

### 步骤 3：版本化
- 重大反转：升级为 `xxx-v2.md`
- 微小修订：在原文档末尾追加"修订记录"
- 完全重写：用新文档替换（决定权归用户所有，按 Q34.1 选定）

### 步骤 4：决策索引同步
- `docs/decisions/README.md` 必须同步更新
- `docs/decisions/CHANGELOG.md` 记录每次修订
- 必须在主索引文档（如 011-pressure-test-v3）里明确引用

### 步骤 5：执行缓冲
- 决策在反转后**强制 7 天冷却期**（除非用户主动加速）
- 这 7 天用于：发现遗漏 / 内部冲突 / 实施影响评估

## 📝 CHANGELOG 模板

每次决策修订必须在 `docs/decisions/CHANGELOG.md` 追加条目：

```markdown
## YYYY-MM-DD: [决策编号] [修订类型]

**修订前**：[原决策摘要]
**修订后**：[新决策摘要]
**修订原因**：[具体场景 / 反例 / 压力测试结果]
**影响范围**：[涉及的文件 / 代码 / 后续工作]
**关联决策**：[与哪些决策相关]
**修订者**：[用户 / AI / 共同]
```

## 🔴 强制规则

| 编号 | 规则 | 后果 |
|------|------|------|
| 1 | 任何 P0 决策的修订必须经用户明确确认 | 违反 = 决策无效 |
| 2 | 决策修订后 7 天内不得再修订同一决策 | 防止反复跳反 |
| 3 | 每个决策必须明确"与哪些决策冲突" | 隐性冲突 = 文档不完整 |
| 4 | 决策修订必须同步触发关联文档 review | 防止上下游失同步 |
| 5 | 冲突级别 L1 / L2 的修订必须产生新文件 | 不允许在原文件里追加 |

---

## 🤖 AI 协作规则

AI 在协助决策时必须：
1. **明确指出当前决策与历史决策的关系**（"这是反转"、"这是扩展"、"这是无关"）
2. **不允许静默修订** — 任何文档修改必须对用户可见
3. **冲突必须显式化** — 不能为了"看起来协调"而抹平矛盾
4. **历史必须可追溯** — 即使重写也要保留归档版本
