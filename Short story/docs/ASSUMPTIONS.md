## A. 技术栈假设

### A1：AI 推理底座

| 假设 | 状态 | 影响 |
|------|------|------|
| Ollama 本地模型可稳定运行在 Windows 11 | ✅ **验证** (实测 0.31.2) | P3 整个底座假设 |
| Ollama 默认模型支持 8k+ 上下文窗口 | ✅ **验证 + 远超预期** | 直接决定 token 预算 |
| Ollama 切换 system prompt 能实现"多 persona" | ✅ **验证** | P14 多 Agent 部署假设 |
| Ollama 采样参数（temperature/top_p）微调 = 反向训练 | ✅ **验证** | P2 反馈闭环的核心 |
| mmx-cli 调用延迟 < 30 秒（云端） | ⚠️ 待验证 | 决定云端协同的可行性 |
| Cloud Relay 模式（密钥托管）可工作 | ⚠️ 待验证 | P4 的前提 |

**A1 实测记录（2026-07-10）**：

| 模型 | 大小 | 上下文 | 短延迟（ping） | 6k prompt 延迟 | persona 切换 | 备注 |
|------|------|--------|----------------|---------------|--------------|------|
| qwen2.5-coder:7b | 4.7GB | 32k | 9.1s | 103s | ✅ 6.4-11s | Coder 模型，**优秀于 JSON 输出 / 设定判断，弱于自由创作** |
| qwythos-mythos:latest | 9.8GB | **1M** | 68.6s | 152s+ | ⚠️ 默认带 thinking | 长上下文之王，但 reasoning 暴露 |

**结论**：
- ✅ 多 persona 切换**已实测可行**（P14 双轨架构成立）
- ✅ 温度采样能影响输出（**误报反馈层可通过 temperature 调节严格度**）
- 🟡 长 prompt 时 qwythos 较慢——但 1M context 是关键吸引力
- 🟡 qwythos 默认展开 reasoning → writing 状态不宜用，**reviewing 多 Agent 可容忍**
- 🔴 **实测暴露的新问题**：qwen2.5-coder 不擅长自由创作，写作状态用它做"实时守护"没问题，但**用 qwythos 做多 Agent 立项会派生声纹可能也不准**——声纹生成需要专门做 benchmark

**对设计的影响**：
- 双模型策略比之前更必须：**qwen2.5-coder 用于一切结构化判断**，**qwythos 仅用于长上下文创作**
- 还需要**下载一个中文通用对话模型**（如 qwen2.5:7b-chat 或 llama3.1:8b）弥补创作短板

### 🟢 🆕 实测结论（2026-07-10）

**🎯 MVP 主创模型 = `qwen2.5-novelist:latest`**（实测胜出，**已锁定**）

| 模型 | 上下文 | 短延迟 | 中延迟（4-6k） | 中文创作 | 防胡写守护 | 备注 |
|------|--------|--------|---------------|---------|-----------|------|
| **qwen2.5-novelist** ⭐ | **16k** | **4-5s** | 30-40s | 🟢 **优秀** | 🟢 **4-13s** | **MVP 主创（已锁定）** |
| qwen2.5-coder:7b | 32k | 9s | 100s | 🔴 差 | 🟢 12s | 备用（结构化判定） |
| qwythos-mythos:latest | 1M | 68s | 150s+ | 🟡 一般 | 🟡 一般 | 长上下文备用 |
| qwythos-novelist-v2 | 8k | 45-150s | - | 🟢 优秀 | 🔴 **不可用** | 与小说家sys冲突 |
| qwen3.5-novelist | 16k | 178s | - | 🟡 未知 | 🔴 **不可用** | 隐藏thinking 占num_predict 输出空 |

**实测结论**：

- ✅ `qwen2.5-novelist` **是 user-personalized 网文特调模型**——sys prompt 包含中文爽文创作指令
- ✅ 中文创作质量**远超 qwen2.5-coder**，原因：sys prompt 强制爽文风格
- ✅ 4 个 setting-check personas（档案/世界观/人物/节奏）全部**延迟 8-15s 出有效 JSON**
- ✅ 防胡写守护延迟 7-13s，**比 qwen2.5-coder 更快**
- ✅ 默认温度 0.8（高温创造性），可以通过 system prompt override 调到 0.0 做严格判定
- 🟡 num_predict=8192（单次可输 8k tokens）—— 可一次性写整章

**这意味着**：

- ❌ **取消之前的"双模型策略"**——不必再 qwen2.5-coder + qwythos 切换
- ✅ **`qwen2.5-novelist` 一统所有 writing / reviewing 场景**
- ⚠️ 云端 mmx-cli 仍作长上下文（1M）兜底——大窗口情境仍需 mmx-cli

### 🔴 qwythos-novelist-v2 实测失败（已排除）

`qwythos-novelist-v2:latest`（9.8GB，qwen2.5 实测）v2 的 modelfile system prompt 写了"资深小说家 + 直入主题"，**与结构化判定任务根本冲突**：

**实测数据**：
| 测试 | qwythos-novelist-v2 | 评价 |
|------|---------------------|------|
| 简单 ping | 49.8s + 1029字符英文 thinking | 🔴 |
| 中文玄幻创作 | 144.9s + 暴露 `<think>` 标签 | 🔴（3.6x slower than novelist）|
| 防胡写守卫（默认 sys）| 91.0s + 1618字符英文 reasoning + 截断 | 🔴 |
| 防胡写守卫（叠加 check_sys）| 92.3s + 1456字符英文 reasoning + 截断 | 🔴 |
| 单 persona 测试 | 66.8s + 英文步骤 1.2.3.4. | 🔴 |

**核心问题**：
- v2 system prompt 强制"拒绝添加注释/拒绝元数据/拒绝心理过程"
- 但模型遇到长 prompt 必然要 think → 系统提示和实际行为矛盾
- 叠加 check_system 也无法压住——sys prompt 与 check_sys 在同一上下文里冲突
- 总结：**v2 是"作家"特调，只能用于纯写作，不能用于结构化判定**

**qwen2.5-novelist 在防胡写上的优势**：
- system prompt 包含"爽文写作指令"但**没有禁止 thinking 或禁止元数据**
- 叠加 check_sys 时模型能屈能伸——温度 0.0 时保守分析不出 reasoning
- 实测：2 次一致性测试都是 `{"violation": true}` 准确判定（4-5s 延迟）

**结论**：`qwen2.5-novelist` 是**唯一**能统一 6 大场景（防胡写 / 违规词 / 机械表达 / AI味 / 声纹 / 多 Agent）的本地模型。

### 🔴 qwen3.5-novelist 实测失败（额外排除，已确认 MVP）

`qwen3.5-novelist:latest`（6.6GB, qwen3.5:9b 微调，16k context）实测表现：

| 测试 | 结果 |
|------|------|
| 简单 ping | 🔴 178.5s + 1180 tokens（系统激活全部指令） |
| 防胡写（默认 sys + temp 0 + num=1000） | 🟡 88.7s，**JSON 准确** |
| 防胡写（叠加 check_sys + temp 0 + num=1000） | 🔴 129.6s，无意外更慢 |
| 4 personas（默认 sys + num=1000） | 🔴 156-162s，**输出空字符串** |
| 用 num=2000 重测 persona | 🔴 312.5s，eval=2000 上限，**仍空字符串** |

**核心问题**：
- qwen3.5-novelist 与 qwythos-novelist-v2 不同：v2 暴露 `<think>` + 输出英文 reasoning；qwen3.5 是**隐藏 thinking 但用尽 num_predict token**
- 即使 sys temp=0 + num=2000 都**没有产物**——这是模型架构（qwen3.5）层面的 thinking 不受控问题
- **与 v2 不同**：v2 看得见 reasoning 可解析；qwen3.5 看不到但吃光 token
- **结果**：qwen3.5-novelist 完全不能用于结构化判定场景

**qwen2.5-novelist 的核心优势**：
- 默认**无内部 thinking**（qwen2.5 架构特性）
- system prompt 含写作指令但**给 check_sys 让位**——能被 system 覆盖

**结论**：`qwen2.5-novelist` 是**唯一**验证能在 6 大场景都输出有效产物的模型。

### 🚫 三模型失败教训汇总

| 模型 | 失败模式 | 改进方向 |
|------|---------|---------|

| qwythos-mythos | 与 qwythos-novelist-v2 同源，1M context 但慢（68s+） | 仅作长上下文备用 |

**对未来的建议**：
- 如有新版 qwen3.5/4 系列"无 thinking"微调（如 qwen3-novelist-non-thinking）实测可能反转
- **qwen2.5-novelist 仍是 MVP 唯一选择**（除非拉新模型）
