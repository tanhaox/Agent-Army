## 🎯 决策摘要

**用户选择方案 B**：批量导入多本不同类型的网文，作为系统压力测试，**反向暴露系统缺失**。

```
┌────────────────────────────────────────────┐
│ 跑 5-10 本代表作                             │
│      ↓                                     │
│ 自动分析 → 覆盖率统计 → 缺失字段识别     │
│      ↓                                     │
│ 生成"系统缺陷报告"                          │
│      ↓                                     │
│ 迭代优化系统（按优先级）                    │
└────────────────────────────────────────────┘
```

---

## 💬 讨论历程

### 用户的核心需求

> "由作者上传一本网文，通过系统分析，快速将这本书的框架融入当前系统。"

**表面需求**：导入单本网文到系统。

### 用户的深层目的

> "在系统打造好之后，我们还没有开始真正由作者去设定网文故事。但通过跑已有的网络小说，可以查到系统中的一些弊端、缺失项，以及我们还未发现的系统缺失项。"

**深层目的**：用真实网文**反向测试**系统，**发现系统未考虑的字段**。

### 我建议的升级：方案 B（批量）

> "不止 1 本，而是 5-10 本不同类型的代表作。"
> "这样发现系统的缺失可能会更全面。"

### 用户决定

> "我是我的话，我选择方案 B。可以跑多本，可以跑不同的故事类型。"

**确认**：✅ 方案 B 批量导入。

## ✅ 最终设计

### A. 测试集选择（5-10 本代表作）

**选择标准**：
- 不同题材（修仙/都市/科幻/历史/言情）
- 不同频道（男频/女频）
- 不同长度（短篇/中篇/长篇）
- 不同结构（单一主角/群像/穿越/重生）

**推荐 8 本代表作**：

### B. 分析流程

```
┌──────────────────────────────────────────┐
│ Step 1: 文本预处理（10%）                │
│ - 章节切分（识别"第X章"标题）            │
│ - 去除广告/废话                           │
│ - 统计总字数、总章节数                    │
└──────────────────┬───────────────────────┘
                   ↓
┌──────────────────────────────────────────┐
│ Step 2: LLM 智能分析（60%）              │
│ - 调用 mmx-cli，分批分析                  │
│ - 每个章节提取：                          │
│   · 角色（首次出现 + 关系）              │
│   · 重要事件                              │
│   · 地点                                  │
│   · 物品（法宝/武器/秘籍）               │
│   · 伏笔（明/暗）                        │
│   · 时间推进                              │
└──────────────────┬───────────────────────┘
                   ↓
┌──────────────────────────────────────────┐
│ Step 3: 实体合并与去重（20%）            │
│ - 同名角色合并                            │
│ - 同一事件不同章节去重                    │
│ - 时间线排序                              │
│ - 关系网构建                              │
└──────────────────┬───────────────────────┘
                   ↓
┌──────────────────────────────────────────┐
│ Step 4: 映射到系统结构（10%）            │
│ - 检查每个设定能否映射到现有字段          │
│ - 标记"系统支持"vs"系统缺失"            │
│ - 生成迁移建议                            │
└──────────────────┬───────────────────────┘
                   ↓
        生成"系统测试报告"
```

### 关键算法

```python
def analyze_novel_coverage(novel_data, system_fields):
    """分析小说的系统覆盖率"""
    
    coverage = {
        'characters': {'total': 0, 'recognized': 0, 'unrecognized': 0, 'error': 0},
        'events': {'total': 0, 'recognized': 0, 'unrecognized': 0, 'error': 0},
        'items': {'total': 0, 'recognized': 0, 'unrecognized': 0, 'error': 0}
    }
    
    missing_fields = {}
    
    for character in novel_data['characters']:
        coverage['characters']['total'] += 1
        if can_map_to_system(character, system_fields):
            coverage['characters']['recognized'] += 1
        else:
            coverage['characters']['unrecognized'] += 1
            # 找出缺失的字段
            gap = identify_gap(character, system_fields)
            missing_fields[gap['field']] = missing_fields.get(gap['field'], 0) + 1
    
    return coverage, missing_fields
```
