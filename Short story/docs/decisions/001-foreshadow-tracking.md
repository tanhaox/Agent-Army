## 🎯 决策摘要

采用**"作者主动标注 + 系统被动感知"** 的方案：

```
作者主动（标注） → 系统被动（感知 + 提醒）
   ↓                        ↓
 画线 📌 标注             AI 守护栏提醒
 填写载体/层级            标签分类筛选
```

---

## 💬 讨论历程

### 第 1 轮：AI 自动检测方案（被否决）

**方案**：用 LLM 自动扫描章节内容，识别哪些句子是"伏笔"。

**问题**：
- ❌ 单看一句话 = 噪音
- ❌ "原来是父亲留下的一封信" → AI 可能误判
- ❌ 误报/漏报成本高
- ❌ 自动 + 人工确认 = 复杂

**结论**：❌ 方案太复杂，否决。

### 第 2 轮：作者主动标注（采纳）

**方案**：作者写完一句后，**手动点击 📌 按钮**将其标记为伏笔。

**优势**：
- ✅ 简单可控
- ✅ 零误报（作者自己最清楚）
- ✅ 可以补充**备注**（计划出现章节、作用）

**结论**：✅ 采纳此方案作为核心。

### 第 3 轮：二级分类（采纳）

**方案**：伏笔需要更精细的分类，不仅是"人/事/物"。

**用户洞察**：
> "我觉得还可以再细分一下，例如二级或三级分类"

**具体分类**：

```
一级：人 / 事 / 物
二级：人 → 出场 / 退场
      事 → 好事 / 坏事
      物 → 获得 / 损失
```

**优势**：
- ✅ 更精细的故事分析
- ✅ AI 可以推断"故事影响"
- ✅ 时间线展示更清晰

**结论**：✅ 采纳二级分类。

### 第 4 轮：双重层级（采纳）

**方案**：每个伏笔可以同时具有 L1 + L2 双重作用。

**L1（推动剧情）**：基础作用，推动故事向前
**L2（转折开始）**：深层作用，标记故事转折点

**示例**：
- 父亲的遗信 → L1（揭示身世）+ L2（身份大转折）
- 小七的牺牲 → L1（情感冲击）+ L2（主角重新出发）
- 冥蝶义体 → L1（主角变强），但无 L2

**结论**：✅ 双重层级可叠加（可多选）。

### 第 5 轮：3 个创建入口（采纳）

**用户洞察**：
> "在设计时间线和设计人物的时候，其实可以有这样的伏笔"

**结论**：伏笔可在 3 个地方创建：

```
入口 1：写作时（write.html）—— 画线标注
入口 2：时间线设计（timeline.html）—— [+ 添加伏笔]
入口 3：人物设计（character-profile）—— [+ 添加伴随事件]
```

### 5. AI 推断逻辑

**自动建议二级分类**（基于关键词 + 模式）：

```python
SUGGEST_RULES = {
    '人': {
        '出场': [
            r'(?:出现|登场|来|到|发现|遇到)',
            r'(?:原来|竟然).{0,5}(?:是|就是)',
        ],
        '退场': [
            r'(?:死|死亡|牺牲|消失|离开|告别)',
            r'(?:再.{0,3}也?不|再也见不到)',
        ]
    },
    '事': {
        '好事': [
            r'(?:成功|胜利|突破|获得|找到|揭露|揭示)',
            r'(?:原来|真相|谜底)',
        ],
        '坏事': [
            r'(?:失败|死亡|受伤|背叛|威胁|危机|追杀)',
            r'(?:坏|惨|绝望|黑暗)',
        ]
    },
    '物': {
        '获得': [
            r'(?:得到|获得|捡到|收到|拥有|找到).{0,10}',
            r'(?:一封|一把|一枚|一块|一|新).{0,5}(?:信|物|剑|书|箱)',
        ],
        '损失': [
            r'(?:失去|丢失|被偷|被抢|被毁|消失)',
            r'(?:没.{0,3}了|不见了|坏了|碎了)',
        ]
    }
}
```

- "主角获得冥蝶义体" → 🎁 物 · ⬇️ 获得

function suggestSecondary(sentence) {
  for (const [primary, secondaries] of Object.entries(RULES)) {
    for (const [secondary, patterns] of Object.entries(secondaries)) {
      if (patterns.some(p => new RegExp(p).test(sentence))) {
        return { primary, secondary };
      }

## 🚫 已否决的方案

### 方案 A：AI 自动扫描所有句子

**否决原因**：误报率高 + 复杂。

**详细问题**：
- "原来是父亲留下的一封信" → AI 可能误判为"已揭示"而非"伏笔"
- 需要人工确认 → 反而更复杂
- 单看一句话 = 噪音

### 方案 B：四级识别机制（信号检测 → 上下文 → LLM → 人工）

**否决原因**：过度设计。

**详细问题**：
- 实现成本高（LLM 调用成本 + Prompt 工程）
- 维护复杂（多层算法需要协调）
- 作者主动标注已经能解决 80% 的问题

### 方案 C：三级分类

**状态**：暂未实施，可作为未来扩展。

**原因**：当前二级分类已足够精细，再细分会增加 UI 复杂度。
