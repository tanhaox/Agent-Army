## 🚨 7 个严重冲突 + 修正建议

### 冲突 #1：撤销 FastAPI vs 章节级授权的隐藏张力

**问题**：撤销 FastAPI 后，"已授权章节走云端"的双轨路由只能用 CLI 内部逻辑实现。

**修正建议**：保留薄 Cloud Relay 做密钥托管 + 转发，本地 CLI 通过 HTTP 调它。

### 冲突 #2：决策 001 被 F3 反转

**修正建议**：升级决策 001 为 `001-v2-foreshadow-tracking.md`，明确"AI 提议 ≠ AI 自动写入"。

### 冲突 #3：决策 010 的多 Agent 架构已部分反转

**修正建议**：决策 010 重写为 **"单 Agent 多通道（写作）+ 多 Agent 协作（立项/打磨）双轨架构"**。

### 冲突 #4：F5 章节授权语义

**修正建议**：已由 P15 替代，章节级授权机制取消。

### 冲突 #5：本地优先 vs 多 Agent 部署的反差（已被 P15 化解）

**修正建议**：不再以章节授权为维度，改以"writing / reviewing 状态"维度自动切换。

### 冲突 #6：MVP 升级与原"先 CLI 后 Web"的张力

**修正建议**：Web 设计稿 = 数据契约（data contract）；CLI 输出格式必须按 web 字段设计。

### 冲突 #7（v3 新增）：反悔机制与立项会启动器的协同

**问题**：R1 触发全量重算时，若触发的是"设定反转"，必须重新走 P10 立项会，**不能跳过**。

**修正建议**：在 R1 流程里嵌入 P10 检查点——若 git diff 显示设定级别变更（如修改 02-characters.md / 01-world.md），自动触发立项会而非全量重算。
