## 🔍 为什么之前会"打回原型"？

### 原因分析

1. **缺少 `toolConfig`**
   - 之前的配置只有规则和约定
   - 没有定义工具的默认批准行为
   - 每次重启后，Claude Code 恢复到默认的"需确认"模式

2. **配置优先级问题**
   - 项目级配置：`.claude/settings.local.json` (最高)
   - 用户级配置：`~/.claude/settings.json`
   - 如果项目级配置不完整，会被用户级配置覆盖

3. **缺少明确的权限定义**
   - 没有明确说明哪些操作可以自动执行
   - Claude Code 默认采取保守策略（全部要求确认）

## 🛠️ 故障排查

### 问题 1: 配置没有生效

**检查**:
```bash
# 确认文件存在
ls -la .claude/settings.local.json

# 确认 JSON 格式正确
python -m json.tool .claude/settings.local.json
```

**修复**:
- 确保 JSON 格式正确（无语法错误）
- 确保文件在项目根目录的 `.claude/` 文件夹中
- 重启 Claude Code

---

### 问题 2: 部分操作仍然要求确认

**可能原因**:
- 操作匹配了 `requireConfirmation` 列表
- 操作被认为是"危险的"

**解决**:
1. 检查操作是否在 `requireConfirmation.Bash` 列表中
2. 如果不需要确认，从列表中移除
3. 如果需要更精细的控制，添加更具体的模式

---

### 问题 3: 配置被覆盖

**检查**:
- 确认没有其他配置文件覆盖
- 检查 `~/.claude/settings.json` 是否有冲突配置

**解决**:
- 项目级配置（`settings.local.json`）优先级最高
- 确保项目级配置完整
