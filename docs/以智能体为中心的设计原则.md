## 🎯 核心原则

### 1. 为工作流构建，不是 API 端点包装 ⭐⭐⭐⭐⭐

**原则说明**：
- 不要简单地包装现有 API 端点
- 构建深思熟虑、高影响力的工作流工具
- 整合相关操作以实现完整任务
- 专注于智能体实际需要完成的工作流

**示例对比**：

| ❌ 错误做法 | ✅ 正确做法 |
|------------|------------|
| `check_availability()` | `schedule_meeting()` - 整合检查、创建、邀请 |
| `create_event()` | 一次调用完成完整工作流 |
| `send_invitation()` | 减少智能体决策点 |

**实现代码**：

```python
# ❌ API 优先设计
class CalendarSkill:
    def check_availability(self, user, time):
        pass

    def create_event(self, title, time):
        pass

    def send_invitation(self, event, attendees):
        pass

# ✅ 工作流优先设计
class CalendarSkill:
    def schedule_meeting(
        self,
        title: str,
        attendees: List[str],
        duration_minutes: int,
        preferred_time: str = None
    ) -> SkillResult:
        """
        一次性完成会议安排工作流

        工作流：
        1. 检查所有参与者的可用性
        2. 找到最佳时间
        3. 创建事件
        4. 发送邀请

        Returns:
            包含会议详情的结果
        """
        # 实现完整工作流
        pass
```

**优势**：
- 减少上下文窗口使用
- 最小化智能体决策点
- 提供更好的错误处理
- 实现完整任务完成

### 2. 优化有限上下文 ⭐⭐⭐⭐⭐

**原则说明**：
- 智能体有有限的上下文窗口
- 返回高信号信息，不是完整数据转储
- 提供"精简"vs"详细"响应格式选项
- 将上下文预算视为稀缺资源
- 优先使用人类可读的标识符而非技术代码

**实现代码**：

```python
from skill_template_v2 import SkillBase, SkillConfig

class MySkill(SkillBase):
    def __init__(self):
        config = SkillConfig(
            optimize_context=True  # 启用上下文优化
        )
        super().__init__(config)

    def list_resources(self, concise: bool = False) -> SkillResult:
        """
        列出资源（支持上下文优化）

        Args:
            concise: 精简模式，仅返回关键信息

        Returns:
            资源列表
        """
        # 获取完整数据
        full_data = self._fetch_all_resources()

        if concise:
            # 精简模式：仅返回关键字段
            optimized_data = [
                {
                    "id": r["id"],
                    "name": r["name"],
                    "status": r["status"]
                }
                for r in full_data
            ]
            message = f"返回 {len(optimized_data)} 个资源（精简模式）"
        else:
            # 详细模式：返回完整信息
            optimized_data = full_data
            message = f"返回 {len(optimized_data)} 个资源（详细模式）"

        return SkillResult.success(
            data=optimized_data,
            message=message
        )

    def execute(self, **kwargs) -> SkillResult:
        result = self.list_resources(concise=kwargs.get('concise', False))

        # 自动优化上下文
        return self.optimize_result_for_context(
            result,
            concise=kwargs.get('concise', False)
        )
```

**最佳实践**：

| 场景 | 精简模式 | 详细模式 |
|------|---------|---------|
| 列表 | id + name | 完整字段 |
| 搜索 | 前 5 个结果 | 所有结果 |
| 日志 | 错误级别 | 所有级别 |
| 统计 | 总数和平均值 | 详细分布 |

### 3. 设计可操作的错误消息 ⭐⭐⭐⭐⭐

**原则说明**：
- 错误消息应该指导智能体走向正确的使用模式
- 建议具体的下一步操作
- 使错误具有教育意义，不仅仅是诊断
- 帮助智能体通过清晰反馈学习正确的工具使用

**示例对比**：

| ❌ 错误做法 | ✅ 正确做法 |
|------------|------------|
| "Error 404: Not Found" | "资源未找到。尝试使用 list_resources() 查看可用选项" |
| "Invalid input" | "参数 'user_id' 格式无效。预期格式：'usr_123'，实际：'123'" |
| "Permission denied" | "权限不足。需要 'read:users' 权限。尝试使用 check_permissions() 验证" |

**实现代码**：

```python
from skill_template_v2 import SkillBase, ActionableError

class MySkill(SkillBase):
    def execute(self, **kwargs) -> SkillResult:
        try:
            user_id = kwargs.get('user_id')

            # 验证用户 ID 格式
            if not user_id.startswith('usr_'):
                raise self.create_actionable_error(
                    error_message=f"用户 ID 格式无效: {user_id}",
                    suggested_action="请使用格式 'usr_123'，其中 123 是数字 ID",
                    context={
                        "expected_format": "usr_<number>",
                        "actual_value": user_id,
                        "example": "usr_123"
                    }
                )

            # 继续处理...
            return SkillResult.success(data={"user_id": user_id})

        except ActionableError as e:
            # 自动转换为可操作错误消息
            return SkillResult.error_result(
                error=e.get_actionable_message(),
                message="参数验证失败"
            )
```

**错误消息模板**：

```python
# 资源未找到
"资源 '{resource_id}' 未找到。{action}"

# 权限不足
"权限不足：需要 '{permission}' 权限。{action}"

# 参数无效
"参数 '{param}' 无效：{reason}。{action}"

# 速率限制
"速率限制超出。{action}（等待 {seconds} 秒或升级计划）"

# 建议操作的占位符
action = "尝试使用 list_resources() 查看可用选项"
action = "请检查参数格式并重试"
action = "使用 filter='active_only' 减少结果数量"
```

### 4. 遵循自然任务细分 ⭐⭐⭐⭐

**原则说明**：
- 工具名称应反映人类的任务思维方式
- 使用一致的前缀提高可发现性
- 围绕自然工作流设计工具，不是 API 结构
- 考虑用户如何思考和描述任务

**命名规范**：

| 类别 | 前缀 | 示例 |
|------|------|------|
| 日历 | `calendar_` | `calendar_schedule_event`, `calendar_list_events` |
| 邮件 | `email_` | `email_send`, `email_draft`, `email_search` |
| 文件 | `file_` | `file_read`, `file_write`, `file_search` |
| 用户 | `user_` | `user_get_profile`, `user_update`, `user_list` |
| 项目 | `project_` | `project_create`, `project_deploy`, `project_test` |

**实现代码**：

```python
class ProjectManagementSkill(SkillBase):
    """
    项目管理技能

    """

    def project_create(self, name: str, **kwargs) -> SkillResult:
        """创建新项目"""
        pass

    def project_list(self, status: str = None) -> SkillResult:
        """列出项目"""
        pass

    def project_deploy(self, project_id: str, env: str) -> SkillResult:
        """部署项目到指定环境"""
```

### 5. 使用评估驱动的开发 ⭐⭐⭐⭐⭐

**原则说明**：
- 早期创建现实的评估场景
- 让智能体反馈驱动工具改进
- 通过快速原型设计和迭代
- 使用量化指标衡量改进

**6 个评估标准**：

| 标准 | 说明 | 检查 |
|------|------|------|
| **独立** | 不依赖其他问题 | 可以单独运行 |
| **只读** | 仅非破坏性操作 | 不修改数据 |
| **复杂** | 多个工具调用 | 至少 2-3 个工具 |
| **现实** | 基于真实用例 | 人类真正需要 |
| **可验证** | 单一明确答案 | 字符串比较 |
| **稳定** | 不随时间变化 | 避免时间敏感 |

**评估驱动开发流程**：

```python
# 1. 先写评估场景
from shared.testing.evaluation_generator import (
    EvaluationFramework,
    EvaluationScenario
)

framework = EvaluationFramework("my-skill 评估")

# 2. 添加场景（先定义期望行为）
scenarios = [
    EvaluationScenario(
        question="列出所有活跃的项目",
        answer="project-a, project-b, project-c",
        tools_required=["project_list", "filter_by_status"],
        complexity="low",
        metadata={"read_only": True}
    ),
    # ... 更多场景

for scenario in scenarios:
    framework.add_scenario(scenario)

# 3. 保存评估
framework.save(Path("tests/evaluations/my_skill_eval.xml"))

# 4. 实现功能（让评估通过）
# 5. 运行评估并迭代
```

## 📋 设计检查清单

### 工具设计检查

- [ ] **工作流整合**：工具是否整合相关操作，而非暴露原始 API？
- [ ] **上下文优化**：是否提供精简/详细选项？返回高信号信息？
- [ ] **可操作错误**：所有错误消息是否包含建议操作？
- [ ] **自然命名**：工具名称是否符合人类思维？有一致前缀？
- [ ] **评估覆盖**：是否有至少 10 个评估场景？

### 代码质量检查

- [ ] **输入验证**：使用 Pydantic/Zod 验证，包含约束和示例
- [ ] **全面文档**：每个工具有摘要、详细说明、参数、返回值、示例
- [ ] **异步模式**：所有 I/O 使用 async/await
- [ ] **错误处理**：所有外部调用有错误处理，返回 LLM 友好消息
- [ ] **类型安全**：完整类型注解，无 any 类型

### 功能检查

- [ ] **只读提示**：只读操作标记 `readOnlyHint: true`
- [ ] **破坏性提示**：破坏性操作标记 `destructiveHint: true`
- [ ] **幂等性**：安全重试的操作标记 `idempotentHint: true`
- [ ] **外部交互**：与外部系统交互标记 `openWorldHint: true`
