## 📐 模块化设计原则

### 1. 分层架构

所有项目应采用清晰的分层架构：

```
项目/
├── controller/           # 控制层：处理请求和响应
│   └── api.py
├── service/             # 服务层：业务逻辑
│   └── business_logic.py
├── model/               # 模型层：数据定义和操作
│   └── data_model.py
├── utils/               # 工具层：通用函数
│   └── helpers.py
└── config/              # 配置层：配置管理
    └── settings.py
```

#### 层级职责

| 层级 | 职责 | 规则 |
|------|------|------|
| **Controller** | 处理 HTTP 请求、参数验证、返回响应 | ✅ 不包含业务逻辑<br>❌ 不直接访问数据库 |
| **Service** | 核心业务逻辑、流程控制 | ✅ 可调用多个 Model<br>✅ 可调用其他 Service |
| **Model** | 数据定义、数据访问 | ✅ 只处理数据操作<br>❌ 不包含业务逻辑 |
| **Utils** | 通用工具函数 | ✅ 无状态<br>✅ 可被任何层调用 |
| **Config** | 配置管理 | ✅ 统一配置入口<br>✅ 环境变量管理 |

#### 调用规则

```
Controller → Service → Model
    ↓           ↓
   Utils      Utils
    ↓           ↓
  Config     Config
```

**禁止的调用**：
- ❌ Controller → Model（必须通过 Service）
- ❌ Model → Service（Model 不应调用业务层）
- ❌ 跨层访问（遵循逐层调用）

每个类、函数、模块应只有一个改变的理由。

#### 类的设计

### 3. 依赖注入

使用依赖注入，降低耦合度。

#### ❌ 不好的做法（硬编码依赖）

```python
class UserService:
    def __init__(self):
        self.db = MySQLDatabase()  # 硬编码依赖
        self.email_sender = SMTPEmailSender()  # 硬编码依赖
```

#### ✅ 好的做法（依赖注入）

```python
class UserService:
    def __init__(
        self,
        db: Database,
        email_sender: EmailSender,
        logger: Logger
    ):
        self.db = db
        self.email_sender = email_sender
        self.logger = logger

# 使用时注入
service = UserService(
    db=MySQLDatabase(),
    email_sender=SMTPEmailSender(),
    logger=get_logger()
)
```

## 📖 代码可读性规范

### 1. 命名规范

#### 变量命名

| 类型 | 规范 | 示例 |
|------|------|------|
| **普通变量** | 小写 + 下划线 | `user_name`, `total_count` |
| **布尔变量** | is/has/can 开头 | `is_valid`, `has_permission` |
| **常量** | 大写 + 下划线 | `MAX_RETRIES`, `DEFAULT_PORT` |
| **私有变量** | 前缀一个下划线 | `_internal_state` |

#### 函数命名

| 类型 | 规范 | 示例 |
|------|------|------|
| **普通函数** | 动词开头 | `get_user()`, `save_data()` |
| **布尔返回** | is/has/can 开头 | `is_valid()`, `has_permission()` |
| **获取器** | get_ 前缀 | `get_user_name()` |
| **设置器** | set_ 前缀 | `set_user_name()` |

#### 类命名

| 类型 | 规范 | 示例 |
|------|------|------|
| **普通类** | 大驼峰 | `UserService`, `DataModel` |
| **异常类** | Error/Exception 结尾 | `ValidationError` |
| **基类/抽象类** | Base/Abstract 前缀 | `BaseModel`, `AbstractService` |

#### 文件命名

| 类型 | 规范 | 示例 |
|------|------|------|
| **模块文件** | 小写 + 下划线 | `user_service.py` |
| **测试文件** | test_ 前缀 | `test_user_service.py` |
| **配置文件** | 小写 + 下划线/连字符 | `config.py` 或 `config.yaml` |

### 2. 编码格式规范

#### 2.1 避免使用 Emoji 字符 ⚠️

**原因**：
- Windows 命令行编码问题（GBK vs UTF-8）
- 脚本输出可能出现乱码
- 跨平台兼容性问题

**规定**：
- ❌ **禁止**在代码中使用 emoji 字符
- ❌ **禁止**在脚本输出中使用 emoji
- ✅ **允许**在文档中使用 emoji（Markdown 文件）
- ✅ 使用文本替代符号

**文本替代符号**：

| Emoji | 文本替代 | 说明 |
|-------|---------|------|
| ✅ | `[OK]` | 成功 |
| ❌ | `[XX]` 或 `[ERROR]` | 失败/错误 |
| ℹ️ | `[INFO]` | 信息 |
| ⚠️ | `[WARN]` | 警告 |
| 🚀 | (不使用) | 使用描述性文字 |
| 💡 | (不使用) | 使用注释说明 |

**示例**：

```python
# 错误示例 ❌
print("✅ 操作成功")
print("❌ 操作失败")
print("⚠️ 警告信息")

# 正确示例 ✅
print("[OK] 操作成功")
print("[XX] 操作失败")
print("[WARN] 警告信息")
```

**常量定义**：
```python
# 推荐定义状态常量
```

```python
# 计算斐波那契数列的第 n 项
# 使用动态规划优化，时间复杂度 O(n)
def fibonacci(n: int) -> int:
    if n <= 1:
        return n

    # dp[i] 表示第 i 项的值
    dp = [0, 1]

    # 从第 2 项开始递推
    for i in range(2, n + 1):
        # 每一项是前两项之和
        dp.append(dp[i - 1] + dp[i - 2])

    return dp[n]
```

### 2. 配置管理类

```python
# config.py
import os
from pathlib import Path
from typing import Optional
import yaml

class Config:
    """配置管理类"""

    def __init__(self, config_file: str = "config.yaml"):
        """初始化配置

        Args:
            config_file: 配置文件路径
        """
        self.config_file = Path(config_file)
        self._config = self._load_config()

    def _load_config(self) -> dict:
        """加载配置文件"""
        if not self.config_file.exists():
            raise FileNotFoundError(f"配置文件不存在: {self.config_file}")

        with open(self.config_file, 'r', encoding='utf-8') as f:
            return yaml.safe_load(f)

    def get(self, key: str, default: Optional[Any] = None) -> Any:
        """获取配置值

        Args:
            key: 配置键，支持点号分隔（如 'app.name'）
            default: 默认值

        Returns:
            配置值
        """
        keys = key.split('.')
        value = self._config

        for k in keys:
            if isinstance(value, dict) and k in value:
                value = value[k]
            else:
                return default

        return value

    # 便捷方法
    @property
    def app_name(self) -> str:
        return self.get("app.name", "UnknownApp")

    @property
    def debug(self) -> bool:
        return self.get("app.debug", False)

    @property
    def db_host(self) -> str:
        return os.getenv("DB_HOST", self.get("database.host", "localhost"))
```

## ⚠️ 错误处理规范

### 1. 错误预防机制（新增）⭐⭐⭐⭐⭐

每个技能/项目文档应包含错误预防部分，提前识别和防范常见错误。

#### 1.1 Common Mistakes 部分

在 README.md 或技能文档中添加"常见错误"部分：

```markdown
## 常见错误

**错误1名称**
- **问题**: 描述错误现象和后果
- **修复**: 正确的做法
- **检测**: 如何发现这个错误（可选）

**示例**：

**跳过测试验证**
- **问题**: 合并损坏的代码，创建失败的 PR
- **修复**: 在提供选项前始终验证测试通过
- **检测**: 检查是否有"Skip test"或"Force merge"操作
```

#### 1.2 Red Flags 部分

明确定义禁止和强制行为：

```markdown
## 红线规则

**禁止 (Never)**:
- 行为1 - 说明为什么禁止
- 行为2 - 说明为什么禁止

**必须 (Always)**:
- 行为3 - 说明为什么必须
- 行为4 - 说明为什么必须

**示例**：

**Never:**
- 在测试失败时继续执行 - 这会引入损坏的代码
- 在未验证的情况下删除文件 - 可能导致数据丢失
- 使用硬编码的敏感信息 - 存在安全风险

**Always:**
- 在修改数据前进行备份 - 防止数据丢失
- 验证输入参数 - 防止注入攻击
- 记录关键操作 - 便于审计和调试
```

#### 1.3 错误预防检查清单

```python
class ErrorPreventionChecker:
    """错误预防检查器"""

    @staticmethod
    def check_before_deletion(file_path: str) -> bool:
        """删除前的检查"""
        checks = [
            (Path(file_path).exists(), "文件不存在"),
            (not Path(file_path).is_dir(), "不能使用此方法删除目录"),
            (Path(file_path).suffix != ".py", "不能删除 Python 源文件"),
        ]

        for check, error_msg in checks:
            if not check:
                raise ValueError(f"删除检查失败: {error_msg}")

        return True

    @staticmethod
    def check_before_merge(branch: str) -> bool:
        """合并前的检查"""
        # 运行测试
        result = subprocess.run(["pytest", "tests/"], capture_output=True)
        if result.returncode != 0:
            raise ValueError("测试失败，不能合并")

        # 检查分支状态
        status = subprocess.run(["git", "status"], capture_output=True)
        if b"modified" in status.stdout:
            raise ValueError("工作目录有未提交的更改")

        return True
```

#### 5.1 测试验证装饰器

```python
import functools
import subprocess
import logging

def require_tests_pass(test_command: str = "pytest"):
    """
    要求测试通过的装饰器

    Args:
        test_command: 测试命令

    Raises:
        RuntimeError: 当测试失败时
    """
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            logger = logging.getLogger(__name__)
            logger.info(f"运行测试验证: {test_command}")

            # 运行测试
            result = subprocess.run(
                test_command.split(),
                capture_output=True,
                text=True
            )

            if result.returncode != 0:
                error_msg = f"测试失败，无法继续操作:\n{result.stdout}\n{result.stderr}"
                logger.error(error_msg)
                raise RuntimeError(error_msg)

            logger.info("测试验证通过")
            return func(*args, **kwargs)
        return wrapper
    return decorator

# 使用示例
```
