## 📋 目录结构标准

```

│
├── docs/                 # 【文档】全局文档
│
├── archives/             # 【归档】旧项目/废弃项目
│
├── logs/                 # 【日志】全局日志目录
│
├── github_downloads/     # 【外部】第三方下载的代码

├── .claude/              # Claude Code 配置

└── PROJECT_STRUCTURE.md  # 本文档
```

## 🎯 项目分类规则

### 1. Skills（技能类项目）

**定义**：可复用的功能模块，提供特定能力。

**特征**：
- ✅ 功能单一，职责明确
- ✅ 可被其他项目引用
- ✅ 有清晰的 API 接口
- ✅ 可独立运行和测试

**示例**：
- `api_manager` - API 管理技能
- `ollama_ai` - Ollama AI 技能
- `local_ocr` - 本地 OCR 技能

**标准结构**：
```
projects/skills/{skill-name}/
├── README.md                 # 项目说明（必需）
├── DEVELOPMENT.md            # 开发文档（可选）
├── __init__.py               # 包初始化
├── {skill_name}_skill.py     # 主要技能代码
├── config.py                 # 配置管理（可选）
├── requirements.txt          # 依赖清单（如有特殊依赖）
├── start_{skill_name}.bat    # 启动脚本（如需）
├── tests/                    # 测试代码
│   └── test_{skill_name}.py
├── examples/                 # 使用示例
│   └── example_{skill_name}.py
├── docs/                     # 详细文档（可选）
│   ├── SUMMARY.md
│   └── IMPLEMENTATION.md
└── logs/                     # 日志目录
```

---

### 2. Apps（应用类项目）

**定义**：完整的业务应用，提供端到端的解决方案。

**特征**：
- ✅ 有完整的用户界面（Web/CLI）
- ✅ 包含多个功能模块
- ✅ 有独立的配置和数据
- ✅ 可独立部署运行

**示例**：
- `intelligent-tutor` - 智能辅导系统（"给我讲课"）
- `knowledge-base` - 知识库应用

**标准结构**：
```
projects/apps/{app-name}/
├── README.md                 # 项目说明（必需）
├── DEVELOPMENT.md            # 开发文档
├── requirements.txt          # 依赖清单
├── start.bat                 # 启动脚本（必需）
├── .env                      # 环境变量模板（如需）
│
├── backend/                  # 后端代码
│   ├── __init__.py
│   ├── main.py              # 主入口
│   ├── api/                 # API 路由
│   ├── services/            # 业务逻辑
│   ├── models/              # 数据模型
│   └── utils/               # 工具函数
│
├── frontend/                 # 前端代码（如有）
│   ├── static/
│   └── templates/
│
├── data/                     # 数据目录
│   ├── database/            # 数据库文件
│   └── uploads/             # 上传文件
│
├── tests/                    # 测试代码
│   └── test_*.py
│
├── docs/                     # 文档
│   ├── API.md
│   └── ARCHITECTURE.md
│
└── logs/                     # 日志目录
```

---

### 3. Tools（工具类项目）

**定义**：独立的小工具，完成特定任务。

**特征**：
- ✅ 功能单一明确
- ✅ 命令行界面
- ✅ 轻量级，依赖少
- ✅ 可独立运行

**示例**：
- `ddg-search` - DuckDuckGo 搜索工具
- `github-ai` - GitHub AI 工具
- `file-operations` - 文件操作工具

**标准结构**：
```
projects/tools/{tool-name}/
├── README.md                 # 项目说明（必需）
├── requirements.txt          # 依赖清单
├── main.py                   # 主入口（必需）
├── config.py                 # 配置（可选）
├── utils/                    # 工具函数（可选）
├── tests/                    # 测试
│   └── test_*.py
└── logs/                     # 日志目录
```

## 📝 命名规范

### 目录命名

| 类型 | 规范 | 示例 |
|------|------|------|
| **项目目录** | 小写英文 + 连字符 | `api-manager`, `intelligent-tutor` |
| **代码文件** | 小写英文 + 下划线 | `api_manager_skill.py` |
| **类名** | 大驼峰 | `OllamaAISkill` |
| **函数名** | 小写 + 下划线 | `get_api_info()` |
| **常量** | 大写 + 下划线 | `MAX_RETRIES` |

### 禁止的命名

- ❌ 中文目录名（如 `给我讲课`）
- ❌ 空格（如 `my project`）
- ❌ 特殊字符（如 `@#$%`）
- ❌ 混合大小写（如 `MyProject`）

## 🔄 新项目创建流程

### 1. 使用模板创建

```bash
# 创建技能项目
cp -r shared/templates/skill_template projects/skills/my-new-skill

# 创建应用项目
cp -r shared/templates/app_template projects/apps/my-new-app

# 创建工具项目
cp -r shared/templates/tool_template projects/tools/my-new-tool
```

### 2. 手动创建检查清单

创建新项目时，确保包含：

- [ ] **README.md**：项目说明、功能介绍、使用方法
- [ ] **requirements.txt**：依赖清单（如有）
- [ ] **start.bat**：启动脚本（apps 必需）
- [ ] **日志系统**：logs/ 目录和日志配置
- [ ] **测试代码**：tests/ 目录和测试文件
- [ ] **文档**：必要的开发文档

### 3. 新项目信息登记

在 `docs/项目登记表.md` 中记录新项目：

```markdown
## {项目名称}

- **类型**：skill/app/tool
- **创建日期**：2026-02-08
- **用途**：项目用途描述
- **依赖**：主要依赖
- **状态**：active/archived
```

## 📦 项目迁移标准

### 迁移条件

当项目出现以下情况时，应考虑迁移：

- ✅ 项目不再维护 → 迁移到 `archives/`
- ✅ 项目类型分类错误 → 移动到正确的目录
- ✅ 项目结构不符合规范 → 重构后移动

### 迁移步骤

1. **评估项目**：检查项目状态和结构
2. **备份项目**：确保不会丢失代码
3. **更新结构**：按照标准结构重组
4. **更新文档**：修改 README 和相关文档
5. **更新索引**：在 `README.md` 中更新项目列表
6. **清理旧位置**：删除或归档旧目录

### 归档标准

项目满足以下任一条件时归档：

- 功能已被其他项目替代
- 超过 6 个月未维护
- 技术栈过时不再使用
