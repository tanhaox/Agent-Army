## 概述

### 什么是评估驱动开发？

评估驱动开发（Evaluation-Driven Development, EDD）是一种基于 **4 阶段开发模式** 和 **SADD（Subagent-Driven Development）** 的软件开发方法。

**核心理念**：
- 📊 **数据驱动** - 通过量化指标评估质量
- 🔄 **迭代优化** - 持续改进直到达到标准
- 🚦 **质量门控** - 设定明确的质量阈值
- 🤖 **智能审查** - 自动化代码审查和评估

### 与传统开发的区别

| 维度 | 传统开发 | 评估驱动开发 |
|------|---------|-------------|
| 质量保证 | 手动测试 | 自动化评估 |
| 反馈周期 | 长且慢 | 短且快 |
| 迭代方式 | 手动调整 | 自动迭代 |
| 质量标准 | 模糊 | 量化指标 |
| 代码审查 | 人工 | AI 自动 |

## 4 阶段开发流程

### 阶段 1: Research（研究）

**目标**：理解需求，识别风险，制定计划

**活动**：
- 分析任务复杂度
- 识别潜在问题
- 评估技术可行性
- 制定实施计划

**输出**：
- 复杂度评估
- 风险清单
- 实施建议

**示例**：
```python
# 自动化研究阶段
research_result = await workflow._research_stage(tasks)

# 输出示例：
# 复杂度: 2.5/5.0
# 风险: 项目复杂度较高，建议分阶段实施
# 建议: 使用子代理框架并行处理独立任务
```

### 阶段 2: Implementation（实现）

**目标**：使用子代理框架执行任务

**活动**：
- 子代理并行/顺序执行
- 实时代力跟踪
- 自动错误处理

**输出**：
- 实现的代码
- 执行结果
- 进度报告

**示例**：
```python
# 子代理执行
impl_result = await workflow._implementation_stage(tasks, mode="sequential")

# 输出示例：
# 成功: 3/3
# 失败: 0
# 得分: 10.0/10.0
```

### 阶段 3: Review（审查）

**目标**：自动化代码质量审查

**活动**：
- 安全检查
- 性能分析
- 代码风格检查
- 文档完整性检查
- 测试覆盖检查

**输出**：
- 问题列表（按严重程度分类）
- 优点列表
- 改进建议
- 质量评分

**示例**：
```python
# 自动代码审查
review_result = await workflow._review_stage(tasks, impl_results)

# 输出示例：
# 关键问题: 0
# 重要问题: 2
# 优点: 5
# 得分: 8.5/10.0
```

### 阶段 4: Evaluation（评估）

**目标**：综合评估，决定是否继续迭代

**活动**：
- 综合评分（实现 + 审查）
- 质量门控判断
- 生成改进建议
- 决定下一步

**输出**：
- 最终评分
- 质量等级
- 决策（完成/迭代）

**示例**：
```python
# 综合评估
eval_result = await workflow._evaluation_stage(tasks, review_result)

# 输出示例：
# 实现得分: 9.0/10.0
# 审查得分: 8.5/10.0
# 最终得分: 8.8/10.0
# 质量等级: good
# 决策: 完成（≥ 7.0 阈值）
```

## 质量门控标准

### 评分系统

**综合评分公式**：
```
最终得分 = 实现得分 × 0.6 + 审查得分 × 0.4
```

**实现得分**：
- 基于任务成功率
- 10 分 = 全部成功
- 0 分 = 全部失败

**审查得分**：
- 基于问题严重程度
- 关键问题扣 2.0 分
- 重要问题扣 0.5 分
- 次要问题扣 0.1 分

### 质量等级

| 等级 | 分数范围 | 含义 | 行动 |
|------|---------|------|------|
| **Excellent** | 9.0-10.0 | 优秀 | 可直接部署 |
| **Good** | 7.0-8.9 | 良好 | 小优化即可 |
| **Acceptable** | 5.0-6.9 | 可接受 | 需修复重要问题 |
| **Needs Work** | 0.0-4.9 | 不足 | 需重新实现 |

### 质量阈值配置

```python
from shared.subagents.workflow import create_workflow

# 严格标准（生产环境）
workflow = create_workflow(quality_threshold=9.0)

# 标准要求（一般项目）
workflow = create_workflow(quality_threshold=7.0)

# 宽松标准（原型开发）
workflow = create_workflow(quality_threshold=5.0)
```

## 实施步骤

### 步骤 1: 创建任务

```python
from shared.subagents.dispatcher import create_task

tasks = [
    create_task(
        task_id="task-1",
        name="实现用户认证",
        description="JWT 认证功能",
        requirements="""
        1. 实现 /auth/login 端点
        2. 实现 /auth/register 端点
        3. 使用 JWT token 机制
        4. 添加密码加密
        """,
        priority=1,
        complexity="high",
        task_type="development"
    ),
    create_task(
        task_id="task-2",
        name="编写测试",
        description="单元测试",
        requirements="""
        1. 测试登录接口
        2. 测试注册接口
        3. 测试 JWT 验证
        """,
        priority=2,
        complexity="medium",
        task_type="testing",
        dependencies=["task-1"]
    ),
]
```

### 步骤 2: 创建工作流

```python
from shared.subagents.workflow import create_workflow

workflow = create_workflow(
    quality_threshold=7.0,      # 质量阈值
    max_iterations=3,            # 最大迭代次数
    enable_review=True,          # 启用代码审查
    enable_progress_tracking=True # 启用进度跟踪
)
```

### 步骤 3: 执行工作流

```python
import asyncio

async def main():
    # 执行完整工作流
    results = await workflow.execute(tasks, mode="sequential")

    # 生成报告
    print(workflow.generate_report())

asyncio.run(main())
```

## 最佳实践

### 1. 任务分解

**好的任务分解**：
```python
tasks = [
    create_task(
        task_id="auth",
        name="实现认证",
        requirements="1. 登录\n2. 注册\n3. JWT",
        complexity="high"
    ),
    create_task(
        task_id="test",
        name="测试认证",
        requirements="1. 单元测试",
        complexity="medium",
        dependencies=["auth"]
    ),
]
```

**不好的任务分解**：
```python
# ❌ 任务太大
create_task(
    name="实现整个用户系统",
    requirements="认证、授权、用户管理、日志..."
)

# ❌ 任务太碎
create_task(name="创建文件")
create_task(name="写第一行代码")
create_task(name="写第二行代码")
```

### 2. 复杂度评估

| 复杂度 | 适用场景 | 模型选择 |
|--------|---------|---------|
| **low** | 简单 CRUD、文档 | haiku/sonnet |
| **medium** | 业务逻辑、测试 | sonnet |
| **high** | 架构设计、核心功能 | opus |

### 3. 迭代次数设置

```python
# 高质量要求（关键项目）
workflow = create_workflow(max_iterations=5)

# 标准要求（一般项目）
workflow = create_workflow(max_iterations=3)

# 快速原型（探索阶段）
workflow = create_workflow(max_iterations=1)
```

### 4. 质量阈值选择

```python

# 开发环境
workflow = create_workflow(quality_threshold=7.0)
```

## 高级技巧

### 1. 自定义评估标准

```python
class CustomWorkflow(EvaluationDrivenWorkflow):
    def _evaluation_stage(self, tasks, review_result):
        # 自定义评估逻辑
        result = await super()._evaluation_stage(tasks, review_result)

        # 添加额外评估维度
        test_coverage = self._check_test_coverage(tasks)
        result.metadata["test_coverage"] = test_coverage

        # 调整评分
        if test_coverage < 0.8:
            result.score *= 0.9

        return result
```

### 2. 分阶段质量标准

```python
# 第一阶段：功能实现（低标准）
workflow_v1 = create_workflow(quality_threshold=6.0)

# 第二阶段：质量提升（高标准）
workflow_v2 = create_workflow(quality_threshold=9.0)

# 先执行 v1，再执行 v2
results_v1 = await workflow_v1.execute(tasks)
if results_v1[-1].success:
    results_v2 = await workflow_v2.execute(tasks)
```

### 3. 回滚机制

```python
# 保存每次迭代的代码
for iteration in range(max_iterations):
    results = await dispatcher.execute(tasks)

    if results[-1].score >= threshold:
        break
    else:
        # 回滚到上一版本
        await rollback_changes()

        # 调整任务后重试
        tasks = adjust_tasks(tasks)
```

## 常见问题

### Q: 如何加快迭代速度？

A:
1. 使用并行执行模式
2. 降低质量阈值（开发阶段）
3. 减少 max_iterations
4. 禁用非必要的审查规则

### Q: 如何提高代码质量？

A:
1. 提高质量阈值
2. 增加 max_iterations
3. 启用所有审查规则
4. 添加自定义质量检查

### Q: 何时使用 EDD？

A:
- ✅ 生产环境开发
- ✅ 需要高质量保证
- ✅ 团队协作项目
- ❌ 快速原型验证
- ❌ 简单脚本开发
