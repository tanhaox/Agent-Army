## 🎯 核心原则

### 第一原则：工具优先 > 手动调试

**永远优先使用服务管理技能**，而不是手动调试！

---

## ❌ 错误的调试流程（耗时 15-20 分钟）

```
发现问题
  ↓
手动查看启动脚本
  ↓
手动编辑代码
  ↓
手动运行 python app.py
  ↓
查看错误日志
  ↓
修改代码
  ↓
再次手动运行
  ↓
（循环往复）
```

**问题**：
- 每次都需要手动启动/停止服务
- 无法快速获取完整响应数据
- 需要创建临时测试文件
- 效率低下，容易遗漏信息

---

## ✅ 正确的调试流程（耗时 2-3 分钟）

```
发现问题
  ↓
立即使用服务管理技能
  ↓
一键测试（自动启动 → 验证 → 返回数据）
  ↓
分析响应数据
  ↓
定位问题
  ↓
修复代码
  ↓
再次验证
```

**优势**：
- 自动完成所有步骤
- 获取完整的响应数据
- 内置日志查看
- 无需创建测试文件

## 📋 标准调试步骤

### 步骤 1：立即使用服务管理技能测试

```python
from service_manager_skill import create_manager

manager = create_manager()

# 一键测试
result = manager.test_service(
    'autogen',
    return_response=True,  # 关键：获取完整响应
    clear_cache=False      # 保留缓存，看当前状态
)
```

### 步骤 2：分析结果

```python
# 检查是否成功
if not result['success']:
    print(f"错误: {result['errors']}")

# 查看完整响应数据
if 'response_data' in result:
    data = result['response_data']
    # 分析 JSON 数据

# 查看日志
manager.tail_logs('autogen', lines=50)
```

### 步骤 3：定位问题

根据响应数据和日志定位具体问题：
- 配置错误
- 代码错误
- 依赖缺失
- 端口冲突

### 步骤 4：修复并验证

```python
# 修复代码后，再次测试
result = manager.test_service('autogen', clear_cache=True)

# 验证修复
if result['success']:
    print("[OK] 问题已解决")
```

## 🎯 常见场景速查

### 场景 1：服务启动失败

```python
manager = create_manager()
result = manager.start_service('autogen', wait=8)

if not result['success']:
    # 查看错误
    print(result['errors'])
    # 查看日志
    manager.tail_logs('autogen')
```

### 场景 2：API 返回错误

```python
def verify_api(url, response):
    data = response.json()
    if 'error' in data:
        return False, f"错误: {data['error']}"
    return True, "API 正常"

result = manager.test_service(
    'autogen',
    verify_func=verify_api,
    return_response=True
)

# 分析具体错误
if not result['success']:
    print(result['response_data'])
```

### 场景 3：性能问题

```python
def check_performance(url, response):
    time = response.elapsed.total_seconds()
    if time > 5.0:
        return False, f"响应过慢: {time:.2f}s"
    return True, f"响应正常: {time:.2f}s"

result = manager.test_service('autogen', verify_func=check_performance)
```

### 场景 4：缓存问题

```python
# 测试不清除缓存
result1 = manager.test_service('autogen', clear_cache=False)

# 测试清除缓存后
result2 = manager.test_service('autogen', clear_cache=True)

# 对比差异
print(f"清除前: {result1['verification']}")
print(f"清除后: {result2['verification']}")
```

## 🔥 必须记住的要点

### 1. 遇到服务问题，第一反应是"用服务管理技能"

**错误的思维**：
- "让我看看启动脚本..."
- "让我手动运行一下..."
- "让我创建一个测试文件..."

**正确的思维**：
- "用服务管理技能测试一下"
- "看看响应数据是什么"
- "检查日志文件"

### 2. 服务管理技能覆盖 99% 的测试场景

| 场景 | 传统方式 | 服务管理技能 |
|------|---------|-------------|
| 启动测试 | 手动启动 | `start_service()` |
| 停止服务 | 手动 kill | `stop_service()` |
| 完整测试 | 多个步骤 | `test_service()` |
| 查看日志 | 打开文件 | `tail_logs()` |
| 清除缓存 | 手动删除 | `clear_cache()` |
| 检查状态 | 手动检查 | `get_service_status()` |
| 获取数据 | 手动请求 | `return_response=True` |
| 自定义验证 | 手动编写 | `verify_func=...` |

### 3. 效率对比

| 操作 | 手动调试 | 服务管理技能 | 提升 |
|------|---------|-------------|------|
| 启动+验证 | 5 分钟 | 30 秒 | 10x |
| 获取响应 | 3 分钟 | 10 秒 | 18x |
| 查看日志 | 2 分钟 | 5 秒 | 24x |
| 完整调试 | 15-20 分钟 | 2-3 分钟 | **7-10x** |

## 🎓 学习要点

### 为什么容易忘记？

1. **旧习惯** - 习惯性地想要"看看发生了什么"
2. **不信任工具** - 担心工具不能提供足够的信息
3. **思维惯性** - 遇到问题先想到手动排查

### 如何形成新习惯？

1. **强制提醒** - 每次都要问自己"我用服务管理技能了吗？"
2. **记录对比** - 记录手动调试 vs 工具调试的时间差异
3. **正向强化** - 每次使用工具后，感受效率提升
