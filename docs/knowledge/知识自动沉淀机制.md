# 知识自动沉淀机制

> 2026-05-07 确立 | 2026-06-01 修正 | 来源: claudeception 设计讨论

---

## 核心原则

**知识提取绑定到决策节点，而非随机触发。**

## 触发机制

用户发出**执行信号**时自动激活：

| 信号 | 含义 |
|------|------|
| 开始开发 / 开始执行 / 开干 | 计划已定，进入实施 |
| 可以推进了 / 没问题开始吧 | 讨论已达成共识 |
| OK / 可以 / 行，开始 | 确认方案，准备动手 |

**不触发**：简单一问一答、单轮操作、还在讨论中的话题。

## 为什么这样设计

```
讨论 → 争论 → 对齐 → 决策 → "开干" ← 此时沉淀
                                  ↑
                            唯一合理的保存点
```

- 讨论过程中内容还在变化，此时保存会产生半成品文档
- AI 不应自己判断"这个值得保存"——是用户的行为（发出执行信号）标记了价值
- 多轮讨论 + 执行信号 = 这套内容经过了充分推敲，值得跨会话复用

## 沉淀范围

- 领域知识（如股票分类标准、AH溢价率公式）
- 架构决策（为什么用P:5→P:1而非权重制）
- 技术方案（skill安装流程、中文改造模板）
- 新安装的工具/skill清单
- 用户纠正反馈

## 存储位置

```
docs/knowledge/
├── README.md           # 知识索引
├── xxx.md              # 一个主题一个文件
```
