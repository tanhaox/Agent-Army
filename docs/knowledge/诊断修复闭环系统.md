# 诊断修复闭环系统

> 来源: 2026-05-07 对话讨论 | 状态: 已实施

---

## 架构

```
user: "自检"
    │
    ▼
project-auditor（6 agent 并行）
    ├─ 代码规范扫描（console.log/密钥/大文件/TODO）
    ├─ 结构规范检查（README/SKILL.md 完整性）
    ├─ Skill 合规审查（三要素: Use when/NOT for/[P:N]）
    ├─ 注册表一致性（CLAUDE.md vs 实际 skill）
    ├─ 文档完整性（docs/adr/ 覆盖）
    └─ Git 状态 + 安全扫描
    │
    ▼ 审计报告（🔴严重/🟡警告/🔵建议 + 分数）
    │
user: "修复"
    │
    ▼
project-fixer（6 agent 并行）
    ├─ console.log  → ai-slop-cleaner
    ├─ 密钥泄露    → py-security / env var
    ├─ 大文件      → code-splitter
    ├─ 缺 README   → 直接生成
    ├─ Skill 合规  → skill-creator
    └─ 注册表 + Git → 直接修复
    │
    ▼ 重跑 audit 验证分数
```

## 两个核心 Skill

### project-auditor (P:2)

- **触发**: "自检"、"审计"、"全面检查"
- **执行**: 运行 `audit.py` 机械扫描 → 6 agent 并行深入分析
- **输出**: file:line 格式分级报告 + 健康分 0-100

### project-fixer (P:2)

- **触发**: "修复"、"fix"、"自动修复" — 也可在 audit 后自然衔接
- **执行**: 读取 audit JSON → 6 agent 并行修复
- **安全**: 修复前 git commit 回滚点、不修改 test 文件

## 问题→修复路由表

| 审计发现 | 修复 Skill |
|---------|-----------|
| console.log 残留 | `ai-slop-cleaner` |
| 硬编码密钥 | `py-security` → env var |
| 大文件 > 1500 行 | `code-splitter` |
| 缺 README.md | 直接生成 |
| SKILL.md 缺三要素 | `skill-creator` |
| 注册表遗漏 | 直接更新 CLAUDE.md |
| TODO 堆积 > 5 | `py-code-health` |
| 文档空洞 | 直接扩充 |
| 注册表 stale | 直接清理 |

## 用户体验

全程不需要记命令：
- "自检" → 诊断
- "修复" → 修复
- "自检然后修复" → 诊断 + 修复一条龙
